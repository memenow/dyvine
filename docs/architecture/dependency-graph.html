Module imports and the third-party SDK surface Dyvine relies on.

Last reviewed: 2026-09-18

The graph below highlights the boundary between Dyvine's own modules (routers, services, core, db, schemas) and the external SDKs Dyvine wraps (f2, boto3, playwright, fastapi, pydantic). Every f2 symbol is resolved through the deferred-import hub core/_lazy_f2; services/websign additionally resolves f2 at patch-install time to wrap its URL builders and raw fetch helpers.

External boundary

  • f2 — third-party Douyin SDK. Imported only from UserService, PostService, LivestreamService, ServiceContainer (constructs the handler), and services/websign.py (wraps the URL builders and raw fetch helpers); never imported from routers, and never at module scope — the services resolve their symbols through core/_lazy_f2, and services/websign.py imports its two patch targets directly inside the install functions (still deferred to first use, never at import time).
  • boto3 — used only inside R2StorageService. Routers and other services touch R2 through that single facade.
  • playwright — used only by services/websign.py to keep one headless-Chromium signing session. The browser signs URLs only; all API traffic and downloads stay on httpx.
  • sqlalchemy[asyncio] / asyncpg / alembic — the persistence stack, used only by db/: the session factory and repositories run async SQLAlchemy over asyncpg, and Alembic versions the schema.
  • fastapi / pydantic / pydantic-settings — the request/response and config layer. Schemas live exclusively in schemas/; settings in core/settings.py.
  • prometheus_client — exposes the /metrics ASGI app and counter/histogram families used by both main and R2StorageService.
For the symbol-level call relationships among these modules, see the call graph.
