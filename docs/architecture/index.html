Dyvine Architecture

Reference diagrams for the Dyvine hermes plugin.

Source layout: src/dyvine/ + src/dyvine_hermes/ Entry point: register(ctx)

Dyvine wraps the third-party f2 Douyin SDK as a hermes-native plugin that delivers asynchronous content downloads, persistent operation tracking, and optional Cloudflare R2 archival. There is no HTTP surface: the gateway loads plugin.yaml plus register(ctx) (directory install) or the hermes_agent.plugins entry point (pip install), and calls tools.

Components

Submit-then-poll (long downloads)

Layered architecture at a glance

  • Plugin shell — src/dyvine_hermes/: register wires every TOOL_SPECS entry to a handler, serializes results to JSON strings (the registry rejects anything else), and registers the bundled dyvine:dyvine-ops skill. Import is side-effect free: no network, no pools.
  • Service — UserService, PostService, LivestreamService, QueueService, ProfileService, delivery channels, R2StorageService, and WatchService in src/dyvine/services. services/websign.py adds the Argus webSign layer: a headless-Chromium signing session (one page that signs URLs only — all traffic stays on httpx) that lazily wraps f2's URL builders.
  • Persistence — Postgres repositories (asyncpg, Alembic-versioned) at src/dyvine/db/; owner heartbeats and an orphan sweep keep state crash-safe. The only state store.
  • Infrastructure — the per-process Engine owns one session factory, one owner identity, a BackgroundTaskRegistry, two named thread-pool executors (R2, R2-head), the f2 DouyinHandler, and a lazily initialized webSign session.
  • Observability — Prometheus counters/histograms, structured JSON logging, correlation IDs, and a passive DatabaseHealthTracker (last-known reachability, never a probe).

Operational invariants

  • Every long-running download returns immediately as a persisted operation row and continues on a tracked background task.
  • Shutdown drains the BackgroundTaskRegistry before reaping executor pools, so an active R2 upload normally finishes (or is cancelled with structured logging) before the process exits; SIGKILL or an overrun shutdown timeout can still cut it short.
  • User-supplied filesystem paths resolve under DOUYIN_DOWNLOAD_ROOT: resolve_within_root() rejects escapes (symlink redirection, traversal segments, absolute paths outside the root) with ValidationError, re-checked after mkdir; the legacy display helper relative_to_download_root() instead renders outside-root absolute paths as bare basenames so stored records never leak layout (see tests/core/test_path_safety.py).
  • The composite Settings validator refuses to boot in non-debug mode when database.url still matches its localhost development default.
  • The webSign layer fails open with explicit signals: builders log a structured warning/error (URL redacted) and only then return the unsigned URL; Argus 403 responses trigger one re-sign plus a single retry, while any other failure re-raises. Treat unsigned fallback as degraded: only Argus-gated endpoints are expected to 403.
  • The orphan sweep fails pending/running rows whose owner stopped heartbeating, so a crashed process never leaves orphaned in-progress rows behind.
  • Tools are single-shot and idempotent; periodic work is driven by hermes cron, never by in-plugin loops. When idle the plugin schedules no work and opens no new connections, though pools may still hold idle keep-alive connections until recycled.
